# Translating the Celestial page

[weewx-celestial manual](https://chaunceygardiner.github.io/weewx-celestial/) · [weewx-celestial on GitHub](https://github.com/chaunceygardiner/weewx-celestial) · [Report an issue](https://github.com/chaunceygardiner/weewx-celestial/issues)

---

As of 7.2 the page is translatable, entirely through WeeWX's own mechanisms — lang files,
`[Texts]`/`$gettext`, and the `[Almanac]` section — the same machinery as
[weewx-skyfield's Sky page](https://chaunceygardiner.github.io/weewx-skyfield/i18n.html).
There are no invented conventions to learn: if you have translated a WeeWX skin before,
this works the same way.

## How it works

Every string the page renders is a **gettext-style `[Texts]` key: the English string is the
key**.  A report falls back to English one string at a time, so a partial translation is
fine — a missing key never breaks the page, it just renders in English.

The words come from four core-standard sources:

| What | Where it is translated |
|---|---|
| Page title, captions, badge states, roster value strings, the pass strings, the footer | `[Texts]` |
| Body and satellite names (dial labels, dome marks and roster rows) | `[Almanac]`, keyed by tag name (`moon = Mond`, `iss = ISS`), beside `moon_phases` |
| Compass cardinals on the dial rim (and the pass rosters' ordinals) | `[Units]` `[[Ordinates]]` `directions` |
| Hemisphere letters in the header's coordinates | `[Labels]` `hemispheres` |

A satellite you add beyond the shipped names (`iss`, `tiangong`, `hst`) gets its display
name the same `[Almanac]` way — set it under `[StdReport]` `[[Defaults]]` so loopdata's
target report sees it too, whichever report that is.

**The live-page twist**: this page is not static — javascript rewrites the badge, the
roster and the dial labels from loop data on every packet.  Everything the javascript
composes is translated once, at report-generation time, and fed to the script as data
(body names, cardinals, and the `[Texts]` strings it needs), so the page stays in one
language end to end with no translation machinery in the browser.  A consequence worth
knowing: changing the report's `lang` takes effect on the next report cycle, when the page
is regenerated — not on the next loop packet.

Times (the clock and the last-update stamp) are not in the dictionary at all: they format
per the report's `lang` through the browser's own locale rules.

## Translating

**Eight translations ship with the skin**, beside `lang/en.conf` — which is the reference
dictionary rather than a translation.  Each one is complete, and a test keeps it that way,
so new strings cannot ship untranslated:

| Language | File | Status |
|---|---|---|
| German | `lang/de.conf` | Partly reviewed as of 7.2 — the vocabulary shared with weewx-skyfield, by native speaker Christian (peters77); this skin's own strings not yet |
| French | `lang/fr.conf` | Partly reviewed as of 7.7 — the vocabulary shared with weewx-skyfield, by native speaker Jacques Terrettaz; this skin's own strings not yet |
| Danish | `lang/da.conf` | Reviewed as of 7.8 — contributed in full by native speaker Gert Andersen |
| Dutch | `lang/nl.conf` | Beta — out for a native-speaker review with Maarten van der Hoeven |
| Spanish | `lang/es.conf` | Beta — awaiting a native-speaker review |
| Italian | `lang/it.conf` | Beta — awaiting a native-speaker review |
| Norwegian (Bokmål) | `lang/no.conf` | Beta — awaiting a native-speaker review |
| Swedish | `lang/sv.conf` | Beta — awaiting a native-speaker review |

Both halves of those statuses are deliberate.

The **shared vocabulary** is the part of each file that is identical to weewx-skyfield's
own lang file — body names, moon phases, hemisphere letters, compass ordinates, satellite
names, all 88 constellation names, and the pass strings shared with its Sky page — and a
test keeps the two extensions in step.  Christian and Jacques read those words in
weewx-skyfield rather than here, which is why the German and French are *partly*
reviewed: the strings that are this skin's own — the page title, the badge states, the
roster wording, the dome panel's eyebrow and install hint and the any-pass roster's
wording (8.0), the countdown row's and comet layer's additions (8.1) — have never been
read by a native speaker of either language.  The Danish carries no such qualification:
Gert Andersen wrote that file entire, this skin's own strings included.

And each status is **dated**, because every reviewed file has grown since it was read.
8.0 added the dome, satellite and pass strings; 8.1 added the countdown row, the comets
and the meteor showers — in every language.  Those additions are complete and pinned by
tests, so nothing renders in English by accident, but no native speaker has read them
yet, and a bare "reviewed" would claim otherwise.  A review's date moves when someone
re-reads the file, not when the file changes.  To use one:

```ini
[StdReport]
    [[CelestialReport]]
        lang = de                # or fr, da, nl, es, it, no, or sv
```

If you read one of these languages natively, a review is the most useful

not more translating but a native eye on the wording — and for all but the
Danish, that includes the strings this skin does not share with
weewx-skyfield.

For any other language, the skin ships its reference dictionary at
`skins/Celestial/lang/en.conf` — every string the page renders, and nothing else (a test
keeps it exact in both directions).  To add a language:

1. Copy `en.conf` to `<code>.conf` in the same `lang` directory (e.g. `fr.conf`) and
   translate the values — the keys stay English.  Translate as much or as little as you
   like; anything you drop falls back to English per string.
2. Point the report at it in `weewx.conf`:

```ini
[StdReport]
    [[CelestialReport]]
        lang = fr
```

Composed strings keep their `{named}` placeholders — reorder them freely, but do not rename
them (a broken placeholder makes that one string fall back to English).  For example:

```ini
[Texts]
    "alt {alt}°" = "Höhe {alt}°"
```

Further languages are welcome as contributions — a lang file is a self-contained, no-code
contribution.

## One place for the whole station: Defaults

Anything under `[StdReport]` `[[Defaults]]` in `weewx.conf` is merged by WeeWX into
**every** report:

```ini
[StdReport]
    [[Defaults]]
        lang = de                      # every skin that ships German goes German
```

`lang = de` selects each skin's own `lang/de.conf` — Seasons, weewx-skyfield's Sky page,
this page and any other skin that ships German switch together.  A skin with no German
simply stays English: a missing lang file is a logged no-op, never an error.

`[[Defaults]]` (or the report's own section) is also the durable home for local overrides:
`weectl extension install` overwrites `skins/Celestial/` — including its lang files — on
every upgrade, while `[[[Almanac]]]`/`[[[Texts]]]` entries in `weewx.conf` survive and are
merged over them.

## Constellations, and loop-data values

The lang files also ship `[Almanac]` `[[Constellations]]` — all 88 constellation display
names, keyed by IAU abbreviation (`Psc = Fische`), identical to weewx-skyfield's — plus
(8.1) the comet display names (`halley`, `hale_bopp`) and the `[[MeteorShowers]]` block,
the twelve IMO majors' names that `almanac.next_meteor_shower.label` and the shower chip
render, all verbatim from weewx-skyfield's files.  The page
itself renders no constellations; the section is there because **loop-data values follow
the language of loopdata's target report**: weewx-loopdata 5.0+ evaluates almanac fields
with the target report's `[Almanac]` texts, so fields like `almanac.moon.label`,
`almanac.moon_phase` or `almanac.mars.constellation.label` arrive already translated when
this report is the target — one language per loopdata instance.  (The data-carrying forms
never translate: `almanac.mars.constellation` reports the Latin name in every language.)
See weewx-skyfield's
[translation manual](https://chaunceygardiner.github.io/weewx-skyfield/i18n.html) for the
tag-side details.

## The dictionary

Every `[Texts]` string the page renders, as shipped, is reproduced on its
own page: [The translation dictionary](i18n-dictionary.md).  A test keys
it to `skins/Celestial/lang/en.conf`, so it cannot drift from what the
skin actually renders.
